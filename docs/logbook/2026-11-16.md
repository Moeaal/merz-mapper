## Results / measurements
- `i2cdetect -l`: buses 0, 1, 2, 4, 5, 7, 9. Header pins 3/5 are expected on **bus 7** (c250000.i2c).
- First scan (01:40): bus 7 empty; bus 1 shows `UU` at 0x25 and 0x40. `UU` = an on-board device already used by a
  kernel driver, **not** the HATs. HATs not yet detected (check 12 V on VIN, wiring to pins 3/5/6). Wiring then done (supply -> both VIN/GND, motors -> A/B, Jetson pins 3/5/6 -> both HATs). After
  fixing one board's connection, bus 7 shows **40, 41** and **70** (the PCA9685 all-call address, expected).
- Bench test (`motor_bench_test.py --bus 7`, 30% duty, 2 s each way, wheels off the ground). Wheel map (one answer
  was typed wrong during the run and corrected straight after: 0x41 A is RL, not FR):

  | HAT | Motor | Wheel | "+" turns it |
  |---|---|---|---|
  | 0x40 | A | front-left | forward |
  | 0x40 | B | front-right | forward |
  | 0x41 | A | rear-left | forward |
  | 0x41 | B | rear-right | forward |

  So 0x40 = front axle, 0x41 = rear axle, A = left, B = right, nothing inverted. All four wheels turned at 30%.

## Problems and how they were solved
- Installed the Raspberry Pi `bcm2835` C library by following the Pi part of the Waveshare wiki. It is for the
  Raspberry Pi's Broadcom chip and is not used on the Jetson -> removed (`sudo make uninstall`, delete the folder).
  Lesson: on the wiki, use only the parts that apply to the Jetson (I2C via `/dev/i2c-*`).
- `motor_bench_test.py` failed first with `No module named 'smbus'` -> `sudo apt install -y python3-smbus`.
- First scan after wiring showed only 41 (and 70): one board was not connected properly; fixed.
- Bus 1 has a kernel-owned device at 0x40, the same address as a HAT. The bench script now refuses any address a
  kernel driver owns, so it cannot write to that chip by mistake.
- Waveshare's own demo leaves the motors running after Ctrl+C (PCA9685 keeps its registers) -> our script always
  stops all channels in a `finally` block and on SIGINT.
